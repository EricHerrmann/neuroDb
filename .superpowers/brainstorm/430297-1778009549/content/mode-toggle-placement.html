A — Sticky header (top of left pane)

Mode toggle stays where it is but is part of the fixed header above the transcript. Always visible, doesn't scroll. Simplest to implement — no structural change, just the fixed-pane CSS makes it sticky naturally.

Pros

  • No change to existing layout logic
  • Mode always visible

Cons

  • Eats vertical space from transcript area
  • Chapter/textbook controls also need to go somewhere

B — Bottom bar (above input, below transcript)

Mode toggle moves into the bottom of the left pane, just above the text input. Both controls are in the same pinned bottom area. Transcript gets the full height above. Like a VSCode status bar combined with editor tabs.

Pros

  • Maximizes transcript height
  • Mode and input close together — natural flow

Cons

  • Mode toggle competes visually with input area
  • Bottom area gets dense

C — Streamlit sidebar

Mode toggle moves into Streamlit's native left sidebar (the collapsible panel). Transcript gets full height. The sidebar already shows DB path and session status — mode fits naturally there. User opens/collapses it as needed.

Pros

  • Transcript + input get full left-pane width
  • Sidebar is collapsible — out of the way when not needed
  • Chapter context could live here too

Cons

  • Mode is hidden when sidebar is collapsed
  • Sidebar adds a nav layer — user must open it to switch modes
