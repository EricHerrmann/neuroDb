A — Sticky Mode Bar

The mode toggle (Local DB / External DB / Neuro-Tutor) sticks to the top of the chat pane and stays visible as the transcript scrolls. Mode controls are always reachable. Workspace pane scrolls independently. Simplest change.

Pros

  • Minimal implementation
  • Mode toggle always visible
  • Workspace already independent

Cons

  • Doesn't fix workspace sync (LOG-002)
  • Chapter/textbook controls not sticky

B — Newest-First Chat

Messages render in reverse chronological order — most recent at the top. The input and mode controls sit at the top too. No scrolling needed for active conversation. Older messages scroll down.

Pros

  • Active turn always visible without scrolling
  • Mode toggle naturally stays in view

Cons

  • Unfamiliar reading direction
  • Streaming new text appears at top — jarring
  • Harder to implement correctly

C — Sticky Controls + Auto-Scroll

Mode toggle (and session status) stick to the top of the chat pane. Chat transcript auto-scrolls to the latest message after each turn. Workspace pane is fully independent. This is the most complete fix for LOG-002/003.

Pros

  • Fixes both LOG-002 and LOG-003
  • Chat scrolls to new content automatically
  • Familiar reading order preserved

Cons

  • Streamlit auto-scroll requires JS injection or scroll container trick
  • More implementation work than A
